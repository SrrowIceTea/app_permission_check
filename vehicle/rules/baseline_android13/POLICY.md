# V-Scanner 项目审计策略 draft-1

这些是待实现、待实验校准的项目策略，不是法律条款，也不是 Android 平台定义。
所有种子规则默认 enabled=0。源码基线版本以各行 android_version 为准，不代表用户设备的版本。
本轮规则 DSL 只作为后续关联分析器的接口草案，尚无执行器。

## P1 权限必要性核查

App 声明敏感车载权限时，结合 App 功能描述、APK 摘要和经审阅的业务必要性策略生成待核查项。
不能单凭申请权限、签名权限申请失败、短时未观察到使用或缺少动态权限弹窗判定过度索权。
结论级别为 candidate。

## R1 实际读取

将 non-null、状态可用且含实际值的属性结果记录为 observed。
必须有 UID 到白名单包名的可靠归属、会话、原始事件 ID 和采集器健康信息。
异常、仅调用入口、订阅成功、包装方法返回默认 0 都不足以单独证明读到值。
多层包装 API 可能重复记录，同一次逻辑读取需去重。
读取事实不等于违规；无事件且采集异常不等于没有读取。

## E1 读取与外发时间关联

候选窗采用 3000 ms，属于项目初始实验参数【需实测校准】，不是平台常量或法律阈值。
读取和外发必须属于同一会话及同一可靠归属包名，时间需校正到统一时基。
条件为 0 <= 外发时刻 - 读取时刻 <= window_ms，并记录时钟偏移及不确定性。
只满足此条件时输出 correlated。载荷内容/指纹匹配及低熵数据误碰撞控制未完成前，不升级为数据泄露结论。
规则引擎不得把普通 HTTP 头、代理端口或相近时间单独视为可信包名归属。

## 适用范围与风险级别

仅用于授权测试，白名单由每次审计会话显式指定，不内置全包扫描默认值。
正式启用需要确认源码与设备的适配、Hook 覆盖和采集健康，再通过靶子实验验证。

severity 是**项目排查优先级，不是法定数据等级**，也不是 GB/T 43697 的分级结论。
按"标识能力"排序——越能直接指向特定车辆或特定行程的，排查优先级越高：

| 属性 | severity | 依据 |
| --- | --- | --- |
| INFO_VIN | high | 直接标识特定车辆，且不可更改 |
| PERF_VEHICLE_SPEED | medium | 与档位组合可反推行驶状态 |
| GEAR_SELECTION | medium | 同上 |
| CURRENT_GEAR | medium | 与 GEAR_SELECTION 同类，同受 CAR_POWERTRAIN 管辖 |
| PERF_ODOMETER | medium | 累计里程近似车辆标识 |
| ENGINE_RPM | low | 动力总成遥测，单独标识能力弱 |
| FUEL_LEVEL | low | 能源遥测，单独标识能力弱 |
| EV_BATTERY_LEVEL | low | 同上 |

这张表覆盖 `vhal_properties` 的全部 8 个属性，与 `seed_policy.py` 的 `selected`
保持一致——**规则库不应该只覆盖其中 3 个**：CURRENT_GEAR 实测可读却无规则，
是已知漏报。新增行的 severity 沿用既有三行的同一判据，不是新发明的分级。

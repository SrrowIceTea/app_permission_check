# 量化实验（2026-09-28）

仅用于授权测试（自有设备、自有 APK）。本文件记录**离线可复现**的实验结论；
原始数据在 `output/experiment-<时间戳>/`，重跑用 `python tools/run_experiments.py`。

**先说清这些数字是什么、不是什么**：下面全是**构造时序**下的**规则语义**结果——
回答的是"给定这样的输入，工具会给出什么"。它们**不是**真实 App 的误判率，
真实比率取决于事件迟到与读取→外发间隔的**分布**，那需要长时间真机采集才能估计。
把语义结果当成发生率是这类实验最常见的过度声称。

## 一、归因（vehicle/traffic/experiment_attribution.py）

四类结果：`correct` / `ambiguous` / `unresolved`，以及最要紧的 **`wrong`**
（归属到了别的包、且没标歧义——会被当真写进报告）。

| 场景 | 结果 |
| --- | --- |
| 只有本包事件 | `correct` 覆盖迟到 **−2000…+2000ms**（恰为 `MATCH_TOLERANCE_MS`），之外 `unresolved`，**从不出错** |
| 竞争者比流晚 65ms（夹具实测值） | `wrong` 出现在 **28/33** 个取值上；`ambiguous` 只在 **−500…+500ms** 内出现 |
| 本包事件比流早 2ms（夹具理想锚点） | **无 `wrong`**；`ambiguous` 只在 −500…+500ms |
| 本包迟到 1500ms、竞争者存在 | `wrong` 出现在竞争者间隔 **−900…+900ms** |

**结论**：容差与歧义窗都精确地按设计工作（解析预测与实测在 **228/228** 个格子上一致）。
但**歧义保护只覆盖 ±500ms 一条窄带**：一旦本包事件离流较远、而另一个 App 的事件更近，
归属会被整条拿走且**不做任何标记**。这正是"错误归因比没有归因更糟"最可能被违反的地方，
已写进 vehicle/traffic/D411 与报告边界。

**夹具坐在安全区里**：实测锚点（自己早 2ms）下从不出错——这解释了为什么单靠夹具校准
看不出这个风险区。

**宽限期（3000ms）的实测权衡**（第二次问的是**同一个 `ts`**，变的是盘上的事件集合）：

| 情形 | 效果 |
| --- | --- |
| 无竞争者、本包迟到 500/1500/2000ms | **救回** `unresolved → correct`（3/5；2500/4000ms 超出容差，救不回） |
| 有竞争者、本包迟到 65/500ms | **降级** `wrong → ambiguous`（2/7）——不再断言，但也不是 `correct` |
| 竞争者在窗口内落盘 | **代价**：原本 `correct` 变 `ambiguous`（2/3） |

宽限期不是白拿的：它用"少几条确定结论"换"少几条错误结论"。报告的 `ambiguous` 条数
受采集时序影响，不全是算法退步。

## 二、关联（vehicle/analyze/experiment_correlation.py）

15 条场景，声明"应当产出哪些 (read, flow) 配对"，与真实 `evaluate_data_egress` 比对：

**precision = 1.0，recall = 1.0，15/15 通过**（TP=4，FP=0，FN=0）。

覆盖的语义：窗口内真配对、窗口边界（恰好 `window_ms` 命中、+1ms 不命中）、窗口外、
只读不发、只发不读、内容不匹配、先后次序倒置、读取失败（D505）、跨包、跨会话、
归因歧义、归因未解析、禁用规则、多属性只命中一个。

**禁用规则用"本会命中"的输入验**：同一条输入在 `enabled=1` 时产出配对、`enabled=0`
时不产出（`proves_disable_takes_effect: true`）。用空输入验禁用是**假通过**——
空输入本来就什么都不产出。

**窗口扫描**：30s 窗口覆盖两个夹具实测间隔（10.6s HTTP / 20.3s HTTPS）并留有余量；
30 001ms 起不再命中。窗口是否够用取决于目标 App 的间隔分布，
**30s 是夹具校准值，不是通用阈值**。

**已知边界（可度量）**：「同名不同值」场景当前**仍判命中**——匹配依据是
"属性名/ID 出现在报文里"（`content_match_basis: request_property_token`），不是值。
实验把这条钉住，将来做值级匹配时能对照起点。这不证明发生了泄露。

## 三、这两套实验自身也踩过坑（已修，已加测试）

1. **混淆矩阵的标签指错**：`band()` 按"键存在就用"取值，扫描 `rival_gap` 时列出来的
   却是**常量** `true_lateness`——计数对、标签全错。看着具体、其实指别的东西。
2. **宽限期模型建反**：写成 `resolve(flow_ts + grace_ms)`，于是宽限一过两个事件的
   delta 都被推出容差，结论从 `ambiguous/wrong` 变成 `unresolved`，实验显示
   **"宽限期会让结果变差"——与事实相反**。真实实现是 `ATTRIB.resolve(entry["ts"])`。
3. **场景表漏了一维**：场景用元组，没有"规则是否启用"这一维，「禁用规则」实际拿
   `enabled=1` 跑，凭空多出一个 `false positive`，算出来的 **precision 0.8 是脚本
   自己的错**。改成具名字典后为 1.0。

三条都是同一个模式：**实验脚本的错误会伪装成被测系统的结论**。
所以两个实验都带交叉核对（解析预测 vs 实现，228/228）与自检用例。

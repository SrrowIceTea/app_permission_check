# 检测分层方案设计说明（2026-11-10）

**状态：L1/L2 分工的方案稿；2026-11-10 起 §1.1 条件 2 与 §1.2 已按实测改口径并落地 L2，
其余章节仍是方案。L2 的实现与数字只记在
[MOBILE_OBSERVED_SURFACE_20261110.md](MOBILE_OBSERVED_SURFACE_20261110.md)，本文不重复。**
**仅用于授权测试（自有设备 / 公开开源样本）。**

数据依据：本文所有数字出自 [MOBILE_SAMPLE_POOL_STRUCTURE_20261110.md](MOBILE_SAMPLE_POOL_STRUCTURE_20261110.md) §8，
方法与边界见 [MOBILE_REACHABILITY_BOUNDARIES_20261110.md](MOBILE_REACHABILITY_BOUNDARIES_20261110.md)。

---

## 0. 要解决的问题

候选生成是**闭集签名表**（`dangerous_apis`，58 条）：没有签名就成不了候选，归属四步根本不会执行。
实测后果（39 个第三方样本，52 个唯一 APK 全部解析成功）：

| 视图 | 值 |
| --- | --- |
| 被闭集看见的敏感 API 形态 | **40 / 630**（平台组，6.3%）；含 GMS 为 40 / 719（5.6%） |
| 缺口上界（品类级口径，含非取数方法） | **93.7%**（平台组）/ 94.4%（含 GMS） |
| 缺口下界（只看类已登记的 266 个签名） | **85.0%** |
| 按调用点加权 | **92.0%**（11,653 中 10,717 不可见） |
| GMS | 89 签名 / 125 调用点 / **0 命中** |
| 国内 SDK（高德/腾讯/百度/autonavi） | **0 签名**——本地无法评估 |

同时另有两个约束，决定了"简单放宽闭集"不可行：

1. **候选会涨一个量级**：9 个跑过可达性（reach9）的样本现有候选 **110** 条；这些样本的敏感签名合计
   **1,227**，即按类级补全后约 **11.2 倍**。
2. **唯一挡噪声的环节本身在失效**：reach9 的 9 个样本里 **7 个**触发"本方法对该样本失效"，
   `unknown` 占非库候选 **54.5%**；9 个 `obf=yes` 的样本**零产物**。

所以本方案不是"加签名"，而是**把输出拆成两层**：能进结论的继续严守"候选 → 已观测"链，
其余敏感面只做覆盖统计、不出结论。

## 1. 两层输出

### 1.1 L1 结论层（进结论）

四条**同时**满足才进 L1：

| # | 条件 | 现状可用字段 |
| --- | --- | --- |
| 1 | 品类在高信号清单内：定位、通讯录、麦克风、相机、剪贴板、设备强标识 | 本轮 §8.3 品类口径 |
| 2 | 归属 = `app_reachable`（含 `via_wrapper` / `app_namespace_derived`），**或 `unknown`（可达性未判定）**；`downgraded_library` / `downgraded_unreachable` 不进结论 | `static_reachability.json` 的 `counts.app_reachable_kind` + 命中点 `reason_code` |
| 3 | 存在"数据离开 App"的路径证据：外发（`target_host` 有值）或落盘 | 动态产物的 `reads/egress` |
| 4 | 可追溯：有规则 ID 或类级派生 ID，能指回签名与代码位置 | 规则库 + 调用图命中点 |

不满足的**不删、不降级为"无风险"**，而是**下沉到 L2**。

#### 条件 2 改口径（2026-11-10）：`unknown` 是正当结论，不是失败

原口径要求"归属必须是 `app_reachable`"，等于把 `unknown` 当成本方法的缺陷。实测不支持这个假设：
改后 9 个样本的 69 个未知命中点里 **56 个（81%）是调用图断裂**（33 个无静态调用方 +
17 个反射/lambda/JNI + 6 个其余断链），属于静态可达性的结构上限，扩映射表消不掉
（见 [MOBILE_REACHABILITY_BOUNDARIES_20261110.md](MOBILE_REACHABILITY_BOUNDARIES_20261110.md) §3.1/§4.1）。
所以：

- **`unknown` 可以进 L1**，但只能进「未判定」子栏，单独列、单独计数，不与已确认项混排；
- L1 的两个数字**必须先拆开写**：`confirmed`（已确认归属）/ `undetermined`（可达性未判定）。
  禁止先把两者相加再当"L1 候选数"——那会把"判不出"说成"检出了"；
- 一条 `unknown` 候选在报告里的呈现，三条缺一不可：
  1. 标题含「可达性未判定」，不得只写规则名或品类名；
  2. 带 `reason_code` **与中文解释**：`wrapper_caller_unknown` = 无静态调用方 / 上溯断链；
     `dynamic_dispatch` = 反射 / lambda / JNI；`obfuscated_class` = 无包名且入口不可达；
     `unattributed_class` = 不属于任何已知命名空间；`app_namespace_derived` = 按前两段前缀推断；
  3. 带固定降级句：**「可达性未判定，不表示未读取，也不表示已排除」**；
- 正文禁止出现「未发现」「已排除」「无风险」三类措辞（`reach_report.EXTRA_LIMITATIONS`
  已把这条写进产物，报告侧照抄即可）；
- 与 L2 分开：`unknown` 是"进了闭集但归属判不出"，L2 是"根本没进闭集"，两者计数不得相加。

存储、已装应用列表这两个品类进不进 L1 要单独论证（`ContentResolver.query` 命中率高但语义最杂），
本文不预设结论。

### 1.2 L2 覆盖统计层（不进结论）

- 输出形态：**每样本 × 每品类**的签名数 / 调用点数 / 已登记数 / 未登记数 + 类清单 + 归属与可达标签。
- 字段命名固定为 `observed_surface`（观测面），**报告中不得出现"发现""违规""风险"**——
  它统计的是"这个 App 碰了哪些敏感 API 形态"，不是"这个 App 违规了"。
- L2 与 L1 的计数**不相加**；L2 里的条目即使看起来很像违规，也只能以"待人工确认"出现。

**2026-11-10 已落地**（实现与实测见 [MOBILE_OBSERVED_SURFACE_20261110.md](MOBILE_OBSERVED_SURFACE_20261110.md)）：

- 作用域是**独立文件** `mobile/rules/targets/sensitive_surface_v1.json`（`MOB-SURFACE-V1`，带 sha256），
  与 `dangerous_apis` / `rules_mobile.db` 物理无关；规则引擎不读它，只由
  `mobile/tools/observed_surface.py` 消费。**这就是"不动规则库"的落地方式**。
- 输出 `observed_surface.json`，与 `static_mobile_supplement.json` 的四桶**并列**；
  `static-manifest.json` 里是独立顶层字段 `observed_surface`，不进 `mobile_supplement`。
- 两个分母必须同时给：`denominators.signature_surface`（签名面）与
  `denominators.call_points`（调用点加权），并附 `invisible.statement_zh` 的**样本内口径降级句**。
- 自证：`mobile/tools/test_observed_surface.py` 现场用 javac + d8 编一个夹具，里面放了一条
  闭集**没登记**的敏感调用；报不出来即说明 L2 只是在复述闭集。

### 1.3 与现有 `unknown` 出口的关系

`unknown`（可达性未知）与 L2（没进闭集）是两件不同的事，**不得互相替代**：

- `unknown` = 进了闭集、判不出归属；
- L2 = 根本没进闭集、归属四步没执行过。

报告中这两类计数必须分开列，否则"unknown 下降"会被误读成"检测变强"。

## 2. 方案成立的前提：覆盖面能不能变成可交付指标

这一节**必须先自证**，不通过就退回"只报不可见比例"。结论先给：**绝对覆盖率不可交付**，
可交付的只是"对某个固定目标集的覆盖 + 样本清单"。下面给出为什么。

### 2.1 三种候选分母

| 分母 | 定义 | 随样本变？ | 可复现？ | 能否对外 |
| --- | --- | --- | --- | --- |
| D1 本次样本出现的敏感签名并集 | 分母从样本里长出来 | **是** | 是 | **否**：换样本分母就变，X% 不可比 |
| D2 类级枚举目标集 `T_vN` | 一份落盘、带版本号与 sha256 的"敏感类 × 方法"清单 | 否 | 是（同 dexdump 指纹下） | 可以，但必须写成"对 `T_vN` 的覆盖" |
| D3 全部 Android 公开 API | 不可穷举、无版本化来源 | 否 | 否 | 否 |

**只能用 D2。** 用 D1 得出的数字（例如本轮 §8 的 719）**只能当内部诊断**，不能写进对外报告——
它随样本池结构漂移，而这正是本次盘点要防止的"数字好看但掩盖失效"。

### 2.2 自证四判据（四条全过才允许写进报告）

1. **分母固定**：`T_vN` 落盘为文件 + sha256 + 版本号；换机器、换批次重算结果一致
   （前提：`dexdump` 指纹一致，见 `dex_callgraph.tool_fingerprint`）。
2. **分子口径唯一**：签名 = `(类, 方法, 描述符)`；**同一签名在多样本出现只算一次**还是**按调用点计数**，
   必须写死并写进报告脚注——本轮两种口径差 1.7 个百分点（93.7% vs 92.0%），不写清就是歧义。
3. **样本集固定**：跑批清单（sha 列表）落盘；换样本必须重算并在报告中换分母版本号。
4. **可反证**：自建夹具作为正向对照，`T_vN` 里夹具应命中的签名必须 100% 命中；
   低于 100% 说明工具链坏了，覆盖率不许发布。

### 2.3 当前状态对应的降级

四判据目前 **2、3 可过，1、4 未建**（没有 `T_vN`，也没有夹具对照断言）。所以现在能报的只有：

- 降级口径 A：**"本次样本内不可见比例 92.0%–94.4%"**（本轮的实测，附样本 sha 清单）；
- 降级口径 B：**"对 `T_vN` 覆盖 X%"**——`T_vN` 建好之后才能报。

**这一条站不住，整个分层就没意义**：L2 的价值全部来自"分母可复现"，否则它只是换了个名字的统计噪音。

## 3. `Build` 字段读取通道（闭集表达力之外）

事实：**38/39 个样本读取 `android.os.Build` 静态字段**——`MODEL` 1255 次、`BRAND` 827、
`MANUFACTURER` 647、`DEVICE` 436、`FINGERPRINT` 207；`Settings$System.DEFAULT_NOTIFICATION_URI` 20 个样本、
`Environment.DIRECTORY_*` 20 个样本同类。这是**设备指纹**的一条独立通道，
且**闭集是方法签名表，补签名永远补不到这里**。

### 3.1 两个可选机制

| 机制 | 可行性 | 成本 | 结论 |
| --- | --- | --- | --- |
| **A 静态字段读取扫描** | 可行：`dexdump -d` 里 `sget-object/iget-object` 的目标含类名+字段名 | 低：本轮临时脚本约 30 行，52 个 APK 全量跑完，与现有 dex 遍历同一遍 | **采用** |
| **B 运行时字段 hook** | 不可行：Frida 无字段 accessor，截不到"读字段"这个动作；只能 hook 调用方类，而调用方是任意类 | 高：等于全量插桩；且只在 ARMED 之后有效 | 不做 |

### 3.2 已知盲区（必须在报告里写）

1. **编译期常量内联**：`Settings.Secure.ANDROID_ID` 这类 `static final String` 的**值**会被内联进字符串池，
   字段访问消失。→ 需要第二条通道：**dex 字符串常量扫描**（`android_id`、`ro.serialno`、`gsf_id` 等），
   成本与 A 同量级（同一遍 dexdump 里取 string pool）。
2. **必须区分 `sget`/`iget` 与 `sput`/`iput`**：只取读，否则"写 Build 字段"（几乎不存在）会混进读计数。
3. **加固/壳会改写字段访问**：本地加固样本 **0 个**，**无法评估**这一条在真实商业 App 上的偏差。

### 3.3 归属层

字段通道**一律进 L2**。理由：读 `Build.MODEL` 是绝大多数 App 的正常行为（崩溃上报、机型适配），
单独出现不构成隐私读取结论；只有当它与"外发 + 归属可达"同时出现时才可提级——而提级规则属于 L1，
不在本文范围。

## 4. 分层之后误报率怎么算

口径必须先定，否则数字没法对外说。

### 4.1 定义

```
L1 误报率 = 人工复核判定"不成立"的 L1 条目数 / L1 条目总数
```

- 分母**只含 L1**；L2 条目、`unknown` 条目都不进分母。
- 分子只认**人工复核结论**，不认"工具二次判断"。

### 4.2 L2 一律不计入

- L2 不出结论 → 不进误报**分子**；
- 也不能因为 L2 大部分是噪声，就说"整体误报率高"（那是把统计层当结论层）；
- 更不能反过来把 L2 当"已排除"来压低误报率。

### 4.3 三个必须同时披露的数

| 数 | 含义 |
| --- | --- |
| L1 结论数 | 进结论的条目 |
| L1 人工复核通过数 | 误报率分子/分母的来源 |
| L2 计数 | **单列**，不与 L1 相加 |

外加 `unknown` 数（既非 L1 也非 L2）。任何只给"误报率 X%"而不给这四个数的报告，视为口径不合规。

### 4.4 本地拿不到的数

人工复核需要人。本地**没有任何复核记录**，所以误报率**本地无法评估**——本文只规定口径，不给数值。

## 5. 候选量级推算（可推算的量级差，不是检出率提升）

reach9 的 9 个样本：现有候选 **110** 条，敏感签名合计 **1,227** 条。

| 样本 | 敏感签名 | 其中已被闭集命中 |
| --- | ---: | ---: |
| chat.simplex.app | 264 | 12 |
| im.status.ethereum | 180 | 11 |
| app.organicmaps.web | 173 | 7 |
| keepass2android | 138 | 10 |
| com.fsck.k9 | 125 | 6 |
| com.kunzisoft.keepass.libre | 125 | 9 |
| com.beemdevelopment.aegis | 112 | 5 |
| org.breezyweather | 55 | 6 |
| org.kiwix.kiwixmobile | 55 | 4 |
| **合计** | **1,227** | **70** |

- 若按**类级**补全闭集，每个不同签名各成一条候选 → 候选从 **110** 涨到 **1,227（11.2 倍）**；
- 增量里 364/630（57.8%）是"整类没登记"，225/630 是"整方法没登记"，只有 1 条是重载差异；
- `unknown` 现为 54.5%，补完后**同比例上升**；7/9 样本可达性已失效 → 新增候选绝大部分只能落 L2。

**不写"检出率提升 X%"**：没有 ground truth（本地没有逐 App 的人工隐私读取标注），
任何提升比例都是编的。能给的只有上面这个可复算的倍数。

## 6. 实施顺序（每步可独立回退，均不碰 `dangerous_apis`）

1. **建 `T_vN` 目标集**（前置，§2 判据 1/4 依赖它）：类级清单 + 版本号 + sha256 + 夹具对照断言。
2. **L2 只读统计**：新增一个输出文件，不改现有候选链、不影响报告结论。
3. **L1 准入门槛**：用现有字段实现四条准入，不新增数据源。
4. **`Build` 字段通道**：静态 `sget/iget` 扫描 + 字符串常量通道，落 L2。
5. **误报率口径**写进报告模板（只写口径，不填数值）。

最贵的不是 1–5 本身，而是 L1 所依赖的**可达性/归属**：9 个样本 7 个失效、混淆样本零产物。
在它修好之前，L1 会因准入条件 2 而几乎全空——那时分层方案仍然成立（L2 照旧出覆盖统计），
但"分层让结论更准"这个收益兑现不了。

---

## 7. 不做 / 边界

- 不改 `dangerous_apis`、不改现有候选链与报告结论；
- 不引 Soot/FlowDroid/新反编译器（仍只用 `dexdump`）；
- 不用 GMS 结果代表国内 SDK；国内 SDK 一格保持**本地无法评估**；
- 不把 L2 当结论、不把 L2 当"已排除"；
- 不输出 `policy_violation`；评分与结论仍只由 L1 + 人工复核产生。

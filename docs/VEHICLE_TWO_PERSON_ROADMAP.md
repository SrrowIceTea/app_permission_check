# V-Scanner 车载端双人开发计划

> **历史快照（2026-11-11 归档，不作当前清单）**：现在什么状态、本周做什么见 [CURRENT_STATUS.md](CURRENT_STATUS.md)。

基线日期 2026-11-04。对象为普通第三方身份运行的 AAOS App，限自有设备和获授权 APK。以 API 35 为主线，API 34 保留通用来源回归。建议先做两个一周迭代，之后按设备与样本可用性扩版本。

### 证据交接

- 第一天在共享基线上定下必填字段，复用已有清单与会话契约。每个案例交付 APK 摘要、普通安装身份、设备 API/指纹、会话、动作时间、读取与流量引用、独立回执及其摘要、采集健康和缺口。代理正文、应用内观察、native 发送与服务端回执分层保留。
- 一人主写采集与 Hook，一人主写评估与交付。共享契约变更单独评审后再接入。封存证据使用独立目录，通过清单交接。可共享的证据先脱敏，失败轮次也保留。
- 两人各自标注同一冻结证据，交换前不看对方答案或工具预测。组织者材料单独保管。按现有 O3 流程请导师或另一位独立复核者处理仲裁、确认负控及签核。只有两人时可以完成试标和分歧登记，指标保留待签状态。正式结果逐层报告 TP、FP、FN、样本数和区间，空分母保留空值。
- 单设备动态任务串行，显式确认 AAOS 指纹、序列号和用户。验收后确认代理、转发和临时测试状态已恢复。两人可同时做离线开发、证据复核和报告重放。

## 本期的技术边界

- 常规第三方关联保留 30 秒。单列明确延迟的漏配及歧义。只有经验证的独立来源证据才能支撑跨窗关联，协作夹具的批次令牌单独评估。
- 新增第三方样本优先产生可复核的业务数据。优先做授权范围内的停车/行驶变化、媒体切后台、断网恢复和用户隔离。休眠/唤醒、点火和 OEM 权限需要相应测试环境与实测证据。
- 扩展 API 33/36 按镜像和设备证据推进。API 36 的 25Q2 第三方车辆属性有明确研究价值，逐项核验对应版本的属性、权限和 API。见 [AOSP AAOS 25Q2](https://source.android.com/docs/automotive/start/releases/aaos-25q2)和[官方车载模拟器文档](https://developer.android.com/training/cars/testing/emulator)。
- 共享内核变更通过 `tools/run_regressions.py --mobile`。验收一条设备路径须提供成功正控、明确负控、身份和健康校验。无法归因的正文继续丢弃，仅保留必要的缺口信息。

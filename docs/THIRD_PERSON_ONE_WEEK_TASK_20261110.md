## 4. 必查场景

| 场景 | 必须验证的显示行为 |
|---|---|
| 仅静态分析完成 | 静态候选不能展示为动态成功或实际外发 |
| 实际取得值 | 按后端证据状态展示，相关事件/规则可核对；读取不能升级为外发 |
| 仅注册 | registration_only明确显示未取得值，不计入成功读取 |
| denied/error/empty等读取未取得值 | read_not_obtained保留具体原因，不合并为没有行为 |
| 健康但本轮无观测 | 不显示安全/合规通过；与Hook缺口或输入缺失分开 |
| general_privacy或关键统计缺失 | not_available/缺字段提示，不默认填0或推断安全 |
| 动态失败或未完成 | 保留可用诊断；遵循现有PDF/报告访问限制，不开放半成品冒充成功 |
| 切换历史/运行任务 | task/session、计数、证据、源码选择及PDF链接不串任务；迟到请求不能覆盖当前任务 |

规则命中、专用业务证据、有限定位实验候选不能相加成一个检测率。
定位实验当前不进默认findings；C不得仅为界面展示把它塞成规则结论。
如文档与后端对某状态的语义矛盾，记录输入与差异交B裁定，不在前端自行定义新判据。

## 6. 验收标准

1. 上述8类场景都有检查项和明确结果；浏览器合成输入只能证明展示逻辑，不算设备行为验证。
2. 缺失与0有区别；仅注册、未取得值和无观测不能显示为安全；状态由现有后端契约提供。
3. 至少一组实际读取产物、一组失败/无观测产物完成页面核对；其他真实材料不存在时明确标未验证。
4. 不同任务间的计数、引用和链接不会串用；没有原事件的字段不得补造。
5. 失败任务的证据访问范围不因测试或修复扩大；截图/公开文档不含坐标、标识、密钥或原始敏感载荷。
6. 已确认的代码问题有修复前失败、修复后通过的有效反例；未发现问题也是合法验收结果。
7. 测试和修改文件≤300行，新增测试信息交B登记；最终commit的C相关检查通过，无新增移动端影响。

不以“截图数量”或“页面看起来正常”替代验收，不承诺找到固定数量bug。
C的验收是开发验证，不冒充人工专家金标准、跨模型签核或真实设备完整验收。

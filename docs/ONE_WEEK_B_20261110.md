## 3. D2 报告投影：按命题裁剪（计划 §2 第 4 条）

改动前第 6 列显示 `business_evidence_total`（整轮值），而计分侧已用
`business_evidence_scoped`。跨命题证据出现时，报告数字会与 `system_stance` 不一致，
构成 C2 反例「借别题证据形成肯定结论」。冻结 6 项的 `total == scoped`，
所以该缺陷**在冻结批次未触发**，只能由合成反例覆盖，本轮如实标注。

| 反例 | 输入 | 改动前 | 改动后 |
|---|---|---|---|
| C2 跨命题证据 | 整轮 3 条别的命题证据、本命题 0 条 | 报告显示 3 | 显示 0，`system_stance=absent`，不形成肯定结论 |
| P4 unscored | `unscored_reason=no_audit_output` | 「—（无观测状态）」 | 「未计分·无采集产物」 |
| 归因错配 | `unscored_reason=reviewers_disagreed` | 缺口段写「无采集产物」 | 写「评审意见未一致，不计分（不是没有行为）」 |
| 旧产物兼容 | 没有 `business_evidence_scoped` 字段 | — | 显示 `—`，不退化成整轮值、不默认 0 |

`tools/test_report_projection.py`（9 项）覆盖上述四种 + bool/负数字段拒绝 + 8 列结构 +
既有 API 签名。`claim_scope.report_cell()` / `evidence_cell()` 是唯一映射来源，
`verdict_rows()` / `build()` / `main()` 签名与 8 列结构不变。
不可判行的 `0` 明确注明**不是健康零命中**，须同看「本命题观测」列。

## 2. 本周目标与明确删减

本周只交三个可独立审查的增量：结果判定更准确、当前采集能力有新基线、有限定位外发匹配有可核验证据。既有前端作为验收入口。
压缩通过减少范围实现；不把三周全部工作压到六天，也不默认靠新人承担剩余工作。

| 优先级 | 本周目标 | 最小交付 |
|---|---|---|
| 必做 M1 | 修“未运行/未观测/有证据”混淆及命题计分 | 现有结果中保留状态与理由；缺必要条件不得算已验证阴性；有反例测试 |
| 必做 M2 | 新 bundle 的真实样本基线及采集故障闭环 | HA/MG4/YAABSA 三个代表性工作流有采集尝试、产物或具体阻塞；旧 7 case 全部登记状态 |
| 争取 M3 | 利用已有坐标摘要，补有限 JSON 字符串坐标对匹配 | 离线正负控通过；有可运行真实定位样本则加一次验证，否则明确仅离线实验能力 |
| 支持项 | 检查现有页面是否如实呈现本周结果 | 少量截图和缺陷单；必要的小修由经验者负责 |

## 4. 三条主线的具体做法

### 4.1 毛宇淇：沿用已有结果体系，修关键误判

检查业务命题与隐私外发命题的证据对应，不能凭 business_evidence_total 总数判任意命题为 present。
缺求值器、缺身份、正文不可见或场景未触达时，使用明确的不可判/未观测说明；任意求值器运行不能支持全部命题的阴性。
保持原 findings_total 只计规则 findings，现有 detection_summary 仍并列规则与业务，不相加成“检测率”。已有 finding_uid 和复核文件不迁移、不重编号。
最小修复优先在现有状态字段和原因中完成；确需增加字段则只增兼容字段，不引入新证据数据库、ID 体系或强制迁移历史会话。
现有页面若没有消费相关诊断，最多补一处字段映射/文字提示；不做页面重设计。未完成/失败任务的报告访问限制保持原契约，不为了展示强行开放半成品报告。

### 4.2 么贵行：用新采集回答“现在能看到什么”

独占现有设备时段，使用已知 Python 3.13、API 35/user 10、Frida 27043 和 attach 入口。自己处理既有环境，不让用户重复 Phase 0 探测。
三条代表工作流优先：HA 电量、MG4 POST、YAABSA send；同 APK 与触发条件优先，HA 控制/503、MG4 WebView、YAABSA playback 作为剩余旧 case 登记，通过/失败/阻塞逐条说明。
采集摘要包含 commit、APK/规则/bundle 摘要、session、设备/user、触发步骤、就绪与失败原因。旧标签不能复用于新证据；缺旧 bundle 时仅报当前基线，不算采集增益。
根据本轮日志只选一个最影响真实数据的缺陷修复，候选如遗漏模块接线、晚启动子进程或完整写入失配；不同时重构三套采集机制。
复用 D419 的完整请求与身份核验，重复正文、多候选继续弃权；保留 STRICT_PACKAGE_SCOPE，不将未归因正文放宽落盘。不能把 ARMED、Cipher 输入或 TLS 字节块直接当成完整上传请求。
后端、媒体或硬件条件不足则保留 blocked；周二仍无真机，不把采购/新机适配列为本周关键路径。普通手机不作为 AAOS 通过证据。

### 4.3 陶俊哲：只补已有值摘要能支撑的最小定位链路

读取现有 `location_forms`/`value_hash` 及完整请求 JSON 字符串叶子，优先支持同一个字符串里的 lat,lon、lon,lat、geo 等成对形态。
仅有单纬度/单经度命中不构成位置配对；坐标形态来源与变换必须写入结果。现有 0,0/越界/不可读状态不因新增匹配被升级。
同 session、包、UID/user、已支持时间基准和候选集合门禁保持；同地点多次读取不强行选唯一来源。数字叶子、不同精度、表单/Protobuf 明确暂不支持。
不要求么贵行改 Hook 提供新明文坐标；离线用合成坐标及冻结事件验证。真实 App 没有该形态不等于没有位置外发。
第一天查当前版本是否登记适用规则；没有则交独立实验输出，标清匹配证据与限制，不编 rule_id、不启用规则凑成功。
至少覆盖同值坐标对、不同值、单坐标、重复来源、异会话/身份、空值/不可用正文六类情况。真实 OwnTracks 样本可用时验证，否则交离线通过加“真实待验证”。

## 5. 一周验收与止损条件

| 项目 | 本周完成判据 | 失败处理 |
|---|---|---|
| 结果口径 | 至少覆盖“仅业务证据、求值器未运行、正文不可见、健康未匹配”四种反例；不能升级为隐私违规或已验证无外发 | 毛宇淇优先修；必要时关闭不可靠断言并保留原因 |
| 采集基线 | 旧 7 case 有状态表，三条代表工作流都有实际尝试及证据/阻塞；失败产物保留 | 若资源阻塞，只交采集基线与阻塞定位，不宣称新增成功 |
| 采集修复 | 选中故障有原失败、修复与同条件复测；跨身份/会话负控不能误归因 | 修复不达标则回退该变更，保留诊断 |
| 定位实验 | 六类正负/歧义用例通过，输出来源/形态/候选和限制；真实验证与离线分列 | 周四仍不稳就只交实验模块，不并入默认判定 |
| 前端抽查 | 现有完成、失败、无观测页面各一例，与后端字段一致 | 有错才小修；没有错即结束，不新增 UI 工作 |
| 回归 | 相关单测、根回归与移动兼容入口无新增失败；缺依赖和原有失败单列 | 新增失败阻断对应改动合并，不压给新人排查 |

每位经验者开工前读对应 DECISIONS；只为实际改动补有意义的反例/回归，单文件仍 ≤300 行；授权白名单、观察不改写、规则来源可追溯保持。

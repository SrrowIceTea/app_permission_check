# 存储 / 加密接入正式链路

仅用于授权测试。`evidence_bundle.build()` 自动读取当前会话的 `audit.jsonl`，
将其脱敏为 `dynamic.storage_crypto`；这不是只保留原始 sidecar 的演示入口。

## 事实和可追溯性

- 仅接受显式目标包名、唯一 `session_id`、正整数进程 ID 的 `storage_crypto` 记录。
  混合会话被排除并写入缺口，不按相似包名、时间近似或全机文件归并。
- `SC#` 是每条存储 / 加密 API 事实，保留 `audit.jsonl` 的物理行号、原 `evt_id`、会话和进程。
  原始文件摘要用于绑定该次数据，原文件不覆盖。
- 文件名、偏好键 / 值、文件 / 加密输入输出均不进入 AI 原文，只有长度、完整性与完整值 SHA-256。
  哈希用于关联，不宣称匿名化后没有重识别风险；未捕全字节不给完整值哈希。
- `FILE_WRITE` 只证明原流写调用成功；`PREF_PUT_STRING` 只证明编辑暂存。
  本适配器没有磁盘读回，因此持久化、其他 App 可读和个人信息泄露均不能由此推出。
  SQLite 文件头、资源库、日志文本、电话号码形状不作为个人信息类别证明。

## 技术观察 SCF# 与评分

| 技术观察 | 条件 | 技术优先级 |
| --- | --- | --- |
| explicit_weak_configuration | 成功 init / doFinal 显式命名 DES / 3DES / RC4 或 ECB | 4 × 3 × 4 = 48 |
| provider_default_mode_unresolved | 成功调用只命名 `AES`，不假定 provider 模式 | 4 × 2 × 2 = 16 |
| repeated_iv_fingerprint | 同包 / 会话 / 进程 / CBC 算法重复 IV 长度及指纹 | 4 × 3 × 3 = 36 |
| encrypted_stream_write_relation | 完整加密输出与 ≤ 5000 ms 后完整流写入相等，或精确 Base64.DEFAULT 编码相等 | 0，关系事实本身不是风险 |

`VSCAN-STORAGE-1` 是本项目声明的技术复核优先级，取本轮技术观察最高值。
没有可评分观察为 `null`，不是安全分零；关系观察零分也不表示全 App 安全。
它不是 CVSS、OWASP 正式分数或法定等级，不擅自给这些技术观察添加法规。
CBC 指纹重复并未验证同密钥；关联是 API 边界相等和顺序，不是污点因果或个人数据绑定。
GCM 观察同样不证明密钥管理、nonce 唯一性或认证标签使用安全。

## 正式 AI 和报告

- 完整证据包保留全部脱敏 `SC#` / `SCF#`。阶段二/三使用有界输入投影：全部 SCF 和每项完整支持 SC 必须保留，其他观察按稳定分组取代表，显式记录总数、输入数、未输入数和原包索引。超出预算即阻断，不静默丢风险依据。
  必须输出 `storage_crypto_review`，逐 SCF 解释或证据不足。
  有 API 无 SCF 用事实摘要；未触发时允许未知，不要求每个 App 必须发现风险。
- 阶段三的技术条目使用 `technical_storage_crypto`，引用实际 SC / SCF，不能改成法规合规结论。
  结构 / 引用 / 证据强度在正式门控和 PDF 加载时重新校验，硬伤不进入报告。
- PDF 证据摘要增加 3.5 节：健康、技术评分、技术观察、原始索引、明确覆盖边界。
  表格展示前 20 条索引并明确提示完整索引在证据包，模型未逐条审阅的观察在输入投影里明确计数；完整事实仍可从证据包追溯。
- 无 `audit.jsonl`、未触发、缺少加密调用、截断、挂载错误都写明未知 / 缺口，不解释为无风险。

定向离线回归：`python -m unittest mobile.ai.test_storage_observations`。
它不替代真实 APK、设备和三阶段模型验收；真实运行以各自新建输出目录为准。

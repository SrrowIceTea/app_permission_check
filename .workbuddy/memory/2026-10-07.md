## 为「真实第三方 APK 检测」编写可执行提示词

产出：`THIRD_PARTY_APK_PROMPT.md`（根目录），含可直接复制给 agent 的完整提示词。

用户诉求：之前用自写夹具测试，现在想找真实移动第三方 APK 跑一遍项目。

### 调研得到的关键环境事实（与文档不一致，重要）

- 当前在跑的是 **`sdk_gphone16k_x86_64` 普通手机模拟器（Android 17 / API 37）**，
  **不是** `Automotive_1408p_landscape`。第三方 App 用手机模拟器反而兼容更好。
- ABI：`x86_64, arm64-v8a`（纯 armeabi-v7a 的包装不上）。
- **frida-server 当前设备上不存在**，需要 `ensure_frida_server()` 拉起（root 身份 + 端口 27043）。
- 主机解释器已从文档里的 `OneKyubey` 路径变为
  `C:/Users/毛宇淇/AppData/Local/Programs/Python/Python313/python.exe`。
  依赖齐全：frida 17.18.0 / mitmproxy 12.2.3 / reportlab 5.0.0。
- `mobile/tools/device_run.py` 的包名与按钮序列**全部写死为夹具**
  （`com.vscanner.privacydemo` / `btnDeviceId` 等），第三方 APK 必须**新写**编排脚本。
- `mobile/hooks/scope.js` 默认白名单是夹具；不给 `--allow-package`
  会**钩子什么都不挂且不报错**（third-party 路径最容易踩的这个坑）。
- `phase7/server.py` 默认 `--android-version 15` 配车载 rules.db；
  移动侧需 `rules_mobile.db` + `--android-version 36`，兼容性未验证，提示词要求 agent 先确认。

### 用户确认的两项决策

1. 检测路径：**静态 + 动态都要**；动态用 **frida-server attach 模式（不用 Gadget）**，
   在模拟器里跑。
2. APK 来源：**从公开应用商店下载**，明确标注为「第三方样本、已声明授权」，
   全程留痕（来源 URL / sha256 / 签名指纹 / 应用版本）。

### 提示词结构（第 0–5 步 + 纪律段）

读文档 → 选下载样本（含选样标准）→ phase7 静态 → 新写脚本做动态 attach →
关联/证据包/报告 → 交付与边界声明。
提示词里点名了三个最易 silent-failure 的点：钩子没挂上 / 白名单没加 / 冷启动竞争
（三者现象都是"零事件"，与"应用没动作"无法区分）。

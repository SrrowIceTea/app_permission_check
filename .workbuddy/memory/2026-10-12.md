## 修复 Windows MAX_PATH 导致「拖入 APK 分析失败」（提交 4a86373）

用户报：前端拖入 APK 显示分析失败 `FileNotFoundError [WinError 3] ...\\vehicle\\w`，并说"报告历史 pdf 都没了"。

**根因（诊断链条值得记住）**：报错里 `vehicle\w` 是界面把路径截断了，真实路径是
`.cache/<sha256>/sources/android/view/accessibility/AccessibilityManager$...Listener.java`，
实测**最长绝对路径 262 字符**，越过 Windows 260 上限。**拆分把 `phase7/` 改名成
`vehicle/workbench/` 后 +11 字符，正好越线**——所以是拆分引入的回归，不是新写的 bug。

迷惑点：`rglob`/`scandir` **照样成功**（用父目录，父目录没超），文件树看着完全正常；
只有对该文件 `stat()`/`open()` 才抛 **WinError 3**（"路径找不到"，不是"文件找不到"）。
调用点在 `jadx.source_tree` 的 `path.stat()`；`Cache.usage/evict` 同病，而它们在
**成功路径**上被 `mark_complete` 调用，一炸就把成功分析记成 failed。

**改法**：新增 `core/static/winpath.py`，路径转 `\\?\` 扩展长度形式，只包 IO 边界
（size/mtime/is_file/read_bytes/rmtree），对外仍传普通 Path。

**两个本机独有的坑（都实测踩过，已写进模块头）**：
1. **后端跑的是 MSYS2 的 Python（`D:/MSYS2/mingw64/bin/python.exe`，PID 命令行只是 `python server.py`）**，
   它是 `os.name=='nt'` 却 `os.sep=='/'` 的怪胎，`os.path.abspath` 返回正斜杠路径；
   而 `\\?\` 只认反斜杠 → 不显式 replace 的话，加了前缀反而**短路径也挂**（WinError 2）。
2. `shutil.rmtree` 内部用 `os.path.join` 拼子路径 → 拼出正斜杠 → 混成 `\\?\D:/a/b`
   → WinError 123，而且 `ignore_errors=True` 会**静默吞掉**（表现为"淘汰执行了、目录还在"）。
   所以 winpath 自己实现了 rmtree（手工反斜杠拼接 + 自底向上删）。

**注意：MSYS2 与标准 CPython 行为不同**，改 core/static 的东西两个解释器都要验。
验证：同一 APK 由 failed → done（classes_written 5379）；run_regressions 11 组全绿；移动端 16/16。
